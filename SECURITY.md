# Security and privacy

Capture is requested through desktop portals. Files, clipboard images and local OCR stay on the computer; the app has no upload endpoint, telemetry or cloud account system. Installation retrieves third-party dependencies. The permission picker controls screen sharing, while audio-only recording reads the selected default PulseAudio-compatible input/output without a screen permission picker.

Use opaque Redact for sensitive content, inspect the exported image, and close/reopen content to discard undo history. Pixelation is not a reliable way to hide secrets. Originals created by the screenshot portal may remain in the backend-managed location; SnagForge does not delete files it did not create. Be aware of that when capturing confidential material.

Use sanitized synthetic examples in public issues. Do not publish a security exploit with private data. Until a hosted repository establishes a private reporting channel, do not send sensitive material to an unverified contact. A later repository maintainer can enable GitHub private vulnerability reporting.
